## 5. Финальная модель доставки individual order

Основной Woo individual order — источник истины. ИЗ-заявка хранит первоначальные данные как историю.

В основном order хранятся актуальные:

- ФИО и телефон получателя;
- город;
- ПВЗ / курьер;
- адрес / ПВЗ / ориентир;
- комментарий;
- carrier;
- payment condition и amount;
- active delivery invoice;
- история delivery invoices.

Существующие meta:

- `_ll_delivery_recipient_name`
- `_ll_delivery_recipient_phone`
- `_ll_delivery_city`
- `_ll_delivery_preference`
- `_ll_delivery_location`
- `_ll_delivery_request_note`

Условия:

1. `undecided` — временно не определено.
2. `free` — LoraLeya не берёт оплату доставки.
3. `invoice` — отдельный Woo delivery payment order.
4. `buyer` — клиент платит перевозчику напрямую.

Defaults:

- 5Post Москва/МО → `free`, `0 ₽`.
- 5Post другой регион → `invoice`, `250 ₽`.
- СДЭК / Яндекс → `buyer`.
- До active invoice менеджер может переопределить условие.

Delivery invoice:

- отдельный Woo order только с `WC_Order_Item_Shipping`;
- не меняет product total основного заказа;
- не содержит product lines и КИЗ;
- не участвует в individual marking и manager-confirmation workflow;
- получает billing/customer data основного заказа;
- оплачивается стандартным Woo order-pay через YooKassa;
- customer invoice отправляется отдельно.

Display numbering:

- main №949;
- delivery №949/Д;
- следующий №949/Д-2, затем №949/Д-3.

Technical Woo ID и order key не меняются. Проверенная chain: `ИЗ-948 → Woo №949 → delivery technical №950/951/952`.

Lock/edit rules:

- одновременно только один active unpaid invoice;
- option-lock owner + TTL `120 sec` + `try/finally` + stale recovery;
- unpaid invoice отменяется, но не удаляется;
- active unpaid блокирует delivery data/financial conditions;
- paid блокирует carrier/city/address/condition/amount; разрешены только ФИО и телефон;
- automatic delivery доплаты/refunds не реализованы.

Completed guard:

- `undecided` блокирует;
- `invoice` без paid delivery order блокирует;
- `free` и `buyer` разрешают Completed;
- guard работает до second-receipt callback.

`application → agreement → Woo order → product payment → callback → first receipt → marking/KIZ → delivery invoice/payment → Completed → second receipt → KIZ circulation exit`.
