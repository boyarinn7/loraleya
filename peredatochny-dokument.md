## 4. ГЛАВНЫЙ БЛОКЕР: 5POST C2C-ПОСТАМАТ — ПОЛНАЯ ИСТОРИЯ

### 4.1. Проблема (что выяснили тестами)
Магазин в дер. Кузнецово, где **нет постаматов 5Post** (ближайшие в Раменском, соседний город). 5Post в этом случае работает по модели **C2C** (client-to-client): Наталья сама закладывает посылку в постамат. Менеджер 5Post подтвердила: рабочий путь — постамат C2C.

**Симптом на чекауте:** при выборе любого постамата на карте — красное «**Оплата выбранной платёжной системой на данной точке недоступна. Выберите другой способ оплаты в оформлении заказа, либо другую точку выдачи.**»

### 4.2. Что проверяли (хронология тестов — чтобы не повторять)
1. **Постаматы на карте РАБОТАЮТ** — плагин их показывает (напр. OM122268, OM125070 Раменское Михалевича 6А, «Постамат 5post в Пятёрочке», тариф 217.84₽). Значки постаматов отличаются от магазинов. → постаматы поддерживаются плагином.
2. **Причина ошибки оплаты найдена:** в плагине блок «Настройка соответствия платёжных систем» — оба поля («Оплата картой при получении на точке» + «Оплата наличными при получении») жёстко стоят в «**Онлайн-оплата**», без других вариантов (т.к. на сайте один способ оплаты = ЮKassa). Плагин путает «оплата ПРИ ПОЛУЧЕНИИ на точке» и «онлайн-ПРЕДОПЛАТА». Изменить нельзя — других значений в выпадашке нет.
3. **Смена склада не помогла:** пробовали склад Кузнецово → Раменское Михалевича 6А (координаты X=55.567211 Y=38.231357), сохранили, сделали по умолчанию. Ошибка «оплата недоступна» ОСТАЛАСЬ. → дело не в складе.
4. **Подтверждено что это известная недоработка плагина:** в документации ipol другой пользователь (12.02.2026) просит «настройку для включения/отключения вывода способов оплаты в виджете» — той самой опции нет. ipol официально пишет «не представитель 5Post, по сервису не консультируем».
5. **Решение «оплата = косметика?»** не успели проверить через довод заказа до оплаты — Boris перевёл разговор на правильный путь (Open API), т.к. ручное переоформление каждого заказа в ЛК 5Post = неприемлемо для продаваемого сайта.

### 4.3. Документ от менеджера (НЕ тот, что нужен)
Наталья прислала `Widget_Партнеров_5POST__рус_в____1_.docx` — это спека **виджета карты** (отображение точек), НЕ создание заказа. Полезное из него: тип точки приходит в поле **`type`** со значениями `POSTAMAT` / `TOBACCO` / `ISSUE_POINT`. Но метода создания заказа там нет.

### 4.4. РЕШЕНИЕ НАЙДЕНО — открытый SDK + официальная документация API
**Ключевая находка (идея Boris — взять из готового модуля):**
- **Официальная документация API 5Post:** `fivepost.ru/developers`
- **Открытый PHP SDK (MIT):** `github.com/lapaygroup/fivepost-sdk` — `composer require lapaygroup/fivepost-sdk`

**Что есть в SDK (всё подтверждено кодом README):**
- Авторизация: api-key → JWT-токен (живёт 1 час, есть хелпер сохранения). Тестовый контур `API_URI_TEST`.
- **Создание заказа** `createOrdersV1` (одноместный — наш случай) / `createOrders` (V3 многоместный, включается по запросу менеджеру). Поля:
  - `setPaymentType(Order::P_TYPE_PREPAYMENT)` — **ПРЕДОПЛАТА** (чистый тип! решает «оплата недоступна» — заказ оплачен онлайн, на точке не платят).
  - `setPvzId('UUID')` — ID точки выдачи, **сюда идёт UUID постамата**.
  - `setWarehouseId('WH001')` — ID склада отправителя.
  - ФИО, телефон, email, цена, вес, габариты, товары (с маркировкой `setCodeGtg` — для Честного знака!).
- **Список точек** `getPvzList` — у каждой точки поле `type=POSTAMAT`, `cellLimits` (размеры ячейки), `cashAllowed/cardAllowed`. API сам валидирует размер посылки под постамат (виден отказ `REJECTED: PICKUP_POINT_SIZE_VALIDATION`).
- **Создание склада** `addWarehouses` (те же поля, что в плагине — можно через API).
- **Этикетка** `getLabels` (PDF/ZIP штрихкод) — **только для заказов через API V3** (нюанс: для печати этикеток может понадобиться попросить менеджера включить V3).
- **Статусы** заказов (синхронизация), **чеки** (`getReceipts` — с фискальными данными, маркировкой), **отмена**, **расчёт тарифа** `calculationTariff`.
- **Тариф API endpoint:** базовый адрес `api-omni.x5.ru` (виден в логах SDK).

**Нюанс C2C:** явного флага «C2C» в SDK нет. Логика: C2C-постамат задаётся сочетанием склад + точка `type=POSTAMAT`. Проверить на тестовом контуре (создать тестовый заказ на постамат, посмотреть приём API).
