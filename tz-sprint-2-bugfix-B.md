## ПРАВКА B4 — унификация slug индивидуального заказа на `individualnyy-zakaz`

**Проблема (корень):** у страницы индивидуального заказа было ДВА конфликтующих slug. Код темы (header, footer, functions, шаблон) везде использует `custom-order`. А ссылки в гриде главной (`front-page.php:84`) и во всём SEO-контенте (тексты цветов, сценарии) ведут на `individualnyy-zakaz`. Какой бы slug ни стоял у страницы — половина ссылок била мимо → 404.

**Решение (приоритет SEO):** унифицировать ВСЁ на `individualnyy-zakaz` (русский транслит-URL лучше для Яндекса), вычистить `custom-order` из кода.

### Часть на стороне Бориса (wp-admin) — выполняется ОТДЕЛЬНО, не агентом
1. Страницы → «Индивидуальный заказ» (ID 705) → Постоянная ссылка → slug = **`individualnyy-zakaz`**
2. Настройки → Постоянные ссылки → Сохранить (сброс правил)

### Часть агента (код темы) — 5 правок

⚠️ После смены slug у страницы WordPress перестаёт подключать `page-custom-order.php` (он ищет slug `custom-order`) — поэтому шаблон, логику header и JS нужно перепривязать к новому slug, иначе страница откроется пустой на дефолтном `page.php`.

**B4.1 — `header.php`, строка 20:**
```php
$is_custom_order  = is_page('custom-order');
```
→
```php
$is_custom_order  = is_page('individualnyy-zakaz');
```
(имя переменной `$is_custom_order` оставь как есть — это внутреннее имя, не slug)

**B4.2 — `header.php`, строка 26:** в ссылке навигации заменить `/custom-order/` → `/individualnyy-zakaz/`

**B4.3 — `footer.php`, строка 10:** в ссылке футера заменить `/custom-order/` → `/individualnyy-zakaz/`

**B4.4 — `functions.php`, строка 90:**
```php
    if (is_page('custom-order')) {
```
→
```php
    if (is_page('individualnyy-zakaz')) {
```
⚠️ Строку 91 (`wp_enqueue_script('loraleya-custom-order', .../custom-order.js, ...)`) **НЕ трогать** — это имя ассета и путь к JS-файлу, slug там роли не играет, файл `custom-order.js` остаётся как есть.

**B4.5 — переименовать файл шаблона:**
```
page-custom-order.php  →  page-individualnyy-zakaz.php
```
Содержимое файла НЕ менять, только имя. WordPress подключит его к странице по новому slug автоматически.

## ПРАВКА B3 — единый цвет тегов (белые/серые рассогласованы)

**Проблема:** Куренкова — «у одних цветов теги белые, у других серые». Причина: в шаблоне цвет тега берётся из `accent_light` каждого цвета (`taxonomy-pa_fabric_color.php` строка ~314):
```php
    .chc-tag        { border-color: rgba(106,58,122,.3); color: <?php echo $color['accent_light']; ?>; }
```
У разных цветов `accent_light` разный (от `#4a4035` до `#f5f2ec`) — отсюда разнобой.

**Решение:** задать тегам единый брендовый золотой цвет, не зависящий от цвета страницы.

**Найди** строку ~314:
```php
    .chc-tag        { border-color: rgba(106,58,122,.3); color: <?php echo $color['accent_light']; ?>; }
```
**Замени на:**
```php
    .chc-tag        { border-color: rgba(197,165,90,.35); color: #c5a55a; text-decoration: none; }
```

`#c5a55a` — золотой бренд-акцент (используется в теме для золотых элементов). `text-decoration: none` — чтобы теги-ссылки не подчёркивались. Теперь все теги на всех цветах будут одинаково золотыми.

**Если** в `style.css` (строка ~1945) есть конфликтующее правило цвета для `.chc-tag` — проверь, не переопределяет ли оно. Базовое правило в style.css задаёт только размер/паддинги/бордюр (без color) — конфликта быть не должно, но проверь.
