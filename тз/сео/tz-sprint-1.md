## Цель спринта

После Спринта 1 сайт loraleya.ru имеет полный набор SEO-оптимизированных текстов для всех существующих страниц первого уровня. Тексты соответствуют семантике (122 проверенных запроса), позиционированию (премиум-подача, не премиум-продукт), редакционному гайду (тон, терминология, GEO-структура для AI-поиска).

Сайт пока **не открывается для индексации** — это произойдёт в Спринте 4. Спринт 1 готовит контентную базу.

## Разделение обязанностей

**Ты (Спринт-Клод) делаешь сам:**
- Пишешь все тексты (title, description, H1, основной контент, FAQ, подписи к блокам, описания оттенков)
- Принимаешь архитектурные решения по структуре каждой страницы
- Готовишь итоговые артефакты в Markdown

**Ты НЕ делаешь сам, а пишешь ТЗ для Claude Code agent:**
- Любые правки CSS/PHP/HTML темы (в т.ч. grid карточек на главной)
- Создание новых записей в CPT через WP-CLI или код
- Любые изменения в файлах темы / плагинов / БД
- Установка/настройка/удаление чего-либо в WP

**Принцип:** твоя стихия — стратегия и содержание. Стихия Code-агента — реализация в коде. Не пытайся писать код или CSS — пиши инженерное ТЗ, которое Борис отдаст Code-агенту. Code-агент умён, ему достаточно направления и качественных критериев, как и тебе.

**Если правка кода кажется тебе крупной (по твоей оценке потратит много токенов Code-агента) — отдельно пометь в ТЗ, чтобы Борис мог решить запускать или нет.**

## Что должно быть на выходе

### Блок A — Главная страница

1. Title (50-65 символов)
2. Meta description (120-160 символов)
3. Hero-блок: слоган + подзаголовок (можно сохранить существующее «Начните с настроения, мы соберём ваш стол» как поэтическую часть, добавив SEO-богатый подтекст под ним)
4. Подписи ко всем блокам главной (с учётом скриншота: сценарии, палитра, изделия, бренд, финальный CTA)
5. Финальный текст для блока «О бренде» (3-5 предложений)

### Блок B — Расширенные цветовые посадки (2 шт.)

Для **бежевого** и **белого** — отдельные ручные посадки (не шаблон):

- Title (индивидуальный, не по шаблону)
- Meta description (индивидуальный)
- H1
- Расширенный основной текст 1500-2000 знаков:
  - Введение в оттенок
  - Описание характера цвета и переливов
  - Сценарии использования (с какими сценариями сервировки сочетается)
  - Сочетания с интерьером и другими цветами
- FAQ-блок из 5 вопросов с ответами (индивидуальные вопросы, не шаблонные)
- Краткое описание оттенка для блока swatch на главной (2-3 предложения)

### Блок C — Шаблонные цветовые посадки (15 шт.)

Для остальных 15 цветов LoraLeya:

- Title по шаблону «{Цвет}ая жаккардовая скатерть и дорожка — {N} наборов | LoraLeya»
- Meta description по шаблону из стратегии 4.2
- H1
- Шаблонный текст 400-800 знаков (с подставкой описания оттенка)
- FAQ из 2-3 вопросов (можно общие, можно с лёгкой адаптацией под цвет)
- Краткое описание оттенка для swatch (2-3 предложения)

Объём текста — на твоё усмотрение в зависимости от семантики цвета: бирюза/чёрный/графит/зелёный (30-81 фразовых) ближе к верхней границе 800 знаков, остальные ближе к 400.

### Блок D — Страницы сценариев (5 шт.)

Для каждого из 5 сценариев — **Романтический ужин, Семейный обед, Праздничный стол, День рождения, Каждый день**:

- Title (по шаблону из стратегии 4.3)
- Meta description
- H1 (для «Семейный обед» — переименовать в title/H1, но НЕ менять URL)
- Основной текст 1500-2500 знаков
- FAQ из 4-5 вопросов
- **Для Праздничного стола дополнительно:** H2-блоки «Сервировка свадебного стола» и «Сервировка стола на юбилей» (по 300-500 знаков каждый) внутри страницы

### Блок E — ТЗ для Claude Code agent на технические правки

Ты не правишь код сам. Готовишь **два отдельных ТЗ** для Claude Code, оформленных как Markdown-артефакты.

**ТЗ E1 — Правка grid сценариев на главной**

Цель: на главной странице карточки сценариев должны вмещать 5 элементов вместо текущих 4.

Контекст для Code-агента: текущая структура — 1×4 (см. скрин в `block-e1-screenshot-context.md`, описание в `loraleya-strategy-v2.md` Часть 2.1). Карточки находятся на главной странице, в блоке после hero и подзаголовка «Какой стол вы накрываете сегодня?». Файл шаблона — нужно найти в теме `wp-content/themes/loraleya/`, вероятно `front-page.php` или `template-parts/home-scenarios.php` (Code-агент сам определит).

Критерии:
- Возможные раскладки: 2×3 с одной декоративной/CTA-ячейкой, 3+2, или 5 в ряд на десктопе с переломом на меньших экранах — выбирает Code-агент по соображениям дизайна
- Адаптивность сохраняется: planшетный breakpoint (≤1279px), мобильный (≤767px)
- Не используем jQuery (используем нативный CSS Grid или Flexbox — то, что уже в проекте)
- 5-я карточка — «День рождения» (она же появится после ТЗ E2)

**ТЗ E2 — Создание новой записи сценария «День рождения»**

Цель: появилась 5-я запись CPT `scenarios` с slug `den-rozhdeniya`, использующая существующий шаблон `single-scenario.php`, с заполненным контентом (передам отдельным файлом в `block-d4-den-rozhdeniya.md`).

Контекст для Code-агента: 4 существующих сценария — Романтический ужин, Семейный обед, Праздничный стол, Каждый день. CPT `scenarios` уже зарегистрирован. Структура полей — посмотри по любому существующему сценарию.

Критерии:
- Запись создаётся через wp-admin или через WP-CLI (на усмотрение Code-агента — что проще)
- Все поля ACF (или meta-fields) заполнены аналогично существующим сценариям, фактический текстовый контент берётся из `block-d4-den-rozhdeniya.md`
- Карточка ДР появляется в блоке сценариев на главной (это уже после ТЗ E1)
- Конструктор на странице ДР работает: 17 цветов, выбор персон 2/4/6, выбор изделий, sticky total bar

⚠️ Если для создания CPT-записи нужно загрузить фото — пометь как открытый вопрос, фото поставит Куренкова отдельно. Контент текстовый — твой, нумерация фотослотов — на усмотрение Code-агента (используй заглушки `placeholder.jpg` если необходимо).

**Объём пометки на крупные правки**

## Критерии качества

### Что считается good

1. **Title:** содержит главный целевой ключ из семантики (см. карту страница → запросы в `loraleya-semantics-final-v2.md` Часть 4), включает «LoraLeya» через `|`, в диапазоне 50-65 символов.

2. **Description:** содержит вторичные ключи + явный call-to-action («доставка по России», «17 цветов», «бесплатная доставка от 100 000 ₽»), 120-160 символов.

3. **Тексты:** соблюдают паттерн GEO «вопрос — прямой ответ — раскрытие» (см. редакционный гайд в стратегии Часть 3.3) — каждый смысловой блок начинается с извлекаемого ответа в 1-2 предложениях.

4. **Тон голоса:** профессиональный, но не академичный; эмоциональный, но не сентиментальный; уверенный, но не категоричный (см. редакционный гайд Часть 3.1, особенно примеры ❌/✅).

5. **Терминология:** строго по таблице в редакционном гайде Часть 3.2.
   - Используем: жаккардовый, коллекция, сценарий, набор, оттенок, индивидуальный пошив
   - НЕ используем: полиэстер, синтетический, ассортимент, доступный, столовый текстиль (как ключ), не мнётся (как SEO-аргумент)

6. **FAQ:** schema FAQPage в JSON-LD выводится через шаблон страницы (в коде темы — если этого нет, пометь как открытый вопрос и не блокируйся).

7. **Двойная терминология куверт/конверт:** на всех страницах где упоминаются куверты — обязательно дублирование «куверты (конверты для столовых приборов)» хотя бы один раз в тексте.

8. **Внутренняя перелинковка:** в каждом тексте свыше 500 знаков — 3-5 контекстных ссылок (правила в редакционном гайде Часть 3.5).

### Что считается not good

- Title без целевого ключа из семантики
- Title в начале или середине без бренда в конце через `|`
- Description без CTA
- Текст без структуры (сплошной абзац без подзаголовков на >500 знаков)
- Использование запрещённых слов в title/H1
- FAQ из менее 3 вопросов на странице цвета
- Дублирующиеся title между разными страницами
- Перелинковка только в одну сторону (страница цвета должна вести на сценарии, сценарий — на цвета и блог)

## Границы — чего НЕ делать

1. **НЕ менять URL** существующих страниц.
2. **НЕ менять таксономии WC** — `pa_fabric_color`, `pa_razmer-*` и прочие WooCommerce-таксономии.
3. **НЕ трогать корзину и чекаут** (даже в ТЗ для Code-агента).
4. **НЕ трогать товарные карточки** — правка title карточек товаров отложена в Спринт 4.
5. **НЕ создавать новые посадки** (`/nabory/`, `/podarki/`, `/scenarios/noviy-god/`) — Спринт 2 и 3.
6. **НЕ менять страницу `/individualnyy-zakaz/`** — Спринт 2.
7. **НЕ открывать индексацию** — Спринт 4.
8. **НЕ устанавливать Rank Math и любые SEO-плагины** — Спринт 4. Сейчас title/description хранятся через существующий механизм темы — в ТЗ для Code-агента можешь предложить вписать meta-теги через хуки темы либо через ACF-поля если они есть. Не требуй установки нового плагина.
9. **НЕ переделывать дизайн** — только grid сценариев на главной с 4 на 5. Остальное не трогаем.
10. **НЕ писать код сам** — все технические правки через ТЗ для Code-агента (см. Блок E).
