# MVP магазина LoraLeya: интеграция с WC + глобальная корзина

**Ветка:** `feature/wc-cart-integration` (создать от `main`)
**Объём:** 3 атомарных коммита
**Что в скоупе:** только **страница цвета** (`/color/{slug}/`) + глобальная иконка корзины
**Что НЕ в скоупе:** страница сценария (отдельный этап после MVP — другая UX-механика конструктора)

---

## Контекст

Миграция `fabric_color → pa_fabric_color` завершена. Вариативные товары работают, WC технически готов принимать заказы. Сейчас на страницах `/color/{slug}/` кнопки `+`/`−` пишут в localStorage, в реальную WC-корзину товары не попадают. Внизу страницы висит «плавающая полоска» (`#stickyBar`) которая по факту мёртвая — JS не обновляет её сумму.

После MVP: клик `+` добавляет товар в WC через AJAX. Глобальная иконка корзины (золотая сумка-пакет, в правом нижнем углу) дышит когда корзина не пуста, бейдж с количеством. Клик → модалка/bottom-sheet с содержимым WC-корзины + `+`/`−` + «Оформить заказ» → `/cart/`. Старая `#stickyBar` удалена.

---

## Архитектура AJAX (уже готова)

В `functions.php` уже есть 3 AJAX-эндпоинта (расширены при миграции):

- `wp_ajax_loraleya_add_to_cart` — `product_id`, `variation_id`, `variation` (массив атрибутов), `quantity` → `cart_count`, `cart_total`, `cart_key`
- `wp_ajax_loraleya_update_cart_item` — `cart_key`, `quantity` (0 = удалить) → `cart_count`, `cart_total`
- `wp_ajax_loraleya_get_cart` — массив `items` с полями `cart_key`, `product_id`, `variation_id`, `name`, `price`, `quantity`, `subtotal`, `image`, `variation`

В `wp_localize_script('loraleya-main', ...)` уже передаются: `ajax_url`, `nonce`, `cart_url`. Эти эндпоинты **не трогать** в MVP.

## Архитектура страницы цвета (что уже есть)

Список товаров — захардкоженные PHP-массивы в `taxonomy-pa_fabric_color.php`:

- **Готовые наборы** (4 штуки) — кнопки `.btn-set` с `data-item="Набор 4п/140"` и т.д. Соответствуют товару WC ID 50 + вариация по таксономии `pa_razmer-nabora` (slug'и: `4p-140`, `4p-175`, `6p-140`, `6p-175`).
- **Поштучные товары** — два типа:
  - **С вариантами размера** (Дорожка, Скатерть): табы `.prod-size-btn` свапают `data-item` на главной кнопке `.btn-prod`. Слаги размеров: для Дорожки `pa_razmer-dorozhki` (140/175/240/300), для Скатерти `pa_razmer-skaterti` (175/220/240).
  - **Простые** (Салфетка, Куверт): одна кнопка `.btn-prod`, нет табов. Соответствуют товарам WC ID 48 и 49 (simple).

JS `main.js` использует функции `cartRead/cartWrite/cartGet/cartSet` которые читают/пишут localStorage по ключу `loraleya_cart`. Кнопки имеют два состояния (через `renderCartBtn`): `«В корзину»` (когда count=0) и `−/счётчик/+` (когда count>0).

**Маппинг `data-item` → WC сущности:**

| `data-item` | WC product_id | размер-таксономия | размер-slug |
|---|---|---|---|
| `Дорожка 140` | 39 | `pa_razmer-dorozhki` | `140` |
| `Дорожка 175` | 39 | `pa_razmer-dorozhki` | `175` |
| `Дорожка 240` | 39 | `pa_razmer-dorozhki` | `240` |
| `Дорожка 300` | 39 | `pa_razmer-dorozhki` | `300` |
| `Скатерть 175` | 44 | `pa_razmer-skaterti` | `175` |
| `Скатерть 220` | 44 | `pa_razmer-skaterti` | `220` |
| `Скатерть 240` | 44 | `pa_razmer-skaterti` | `240` |
| `Салфетка` | 48 | — (simple) | — |
| `Куверт` | 49 | — (simple) | — |
| `Набор 4п/140` | 50 | `pa_razmer-nabora` | `4p-140` |
| `Набор 4п/175` | 50 | `pa_razmer-nabora` | `4p-175` |
| `Набор 6п/240` | 50 | `pa_razmer-nabora` | `6p-140` ← см. примечание ниже |
| `Набор 6п/175` | 50 | `pa_razmer-nabora` | `6p-175` |

**Цвет** для всех — текущий из URL (`get_queried_object()->slug`), таксономия `pa_fabric_color`.

**Примечание про слаги набора 6п:** в импортере и WC slug'и набора `6p-140` и `6p-175` (без слеша). При этом наборы на 240 и 300 у нас **по контексту** из контекста проекта — это 6п/140 и 6п/175 в плане размера дорожки внутри набора. То есть `data-item="Набор 6п/240"` в шаблоне (с дорожкой 240) → WC slug вариации `6p-140` (потому что именно так названы вариации в WC). Это унаследованная путаница, не пытаться разруливать в MVP. Жёстко зашить маппинг.

## Найденный баг существующего кода

В `taxonomy-pa_fabric_color.php` строка 382: `data-item="Набор 6п/140"` — но это карточка набора **на 240** (см. строки 374–384, текст «Набор на 6 персон · дорожка 240»). Должно быть `data-item="Набор 6п/240"`. Сейчас два разных набора (на 240 и на 140 которого вообще нет в шаблоне) имеют одинаковый `data-item`, что в localStorage сливает их счётчики.

В рамках коммита 1 поправить: строка 382 `data-item="Набор 6п/240"`.

## Последовательность

### Коммит 1: WC-связка для страницы цвета

ТЗ → `01-connect-cart-page-color.md`

Меняется:
- `functions.php` — добавляется хелпер `loraleya_find_variation_id($product_id, $color_slug, $size_slug, $size_taxonomy)` + локализуется JS-карта `LORALEYA_ITEM_MAP` через `wp_localize_script`
- `taxonomy-pa_fabric_color.php` — на каждой кнопке `.btn-prod`, `.btn-set`, `.prod-size-btn` добавляются `data-product-id`, `data-variation-id`. Также фикс бага со строкой 382.
- `assets/js/main.js` — функции `cartRead/cartWrite/cartGet/cartSet` остаются API-обёрткой, но внутри идут к WC AJAX. Кэш в JS-переменной модуля. Логика табов размеров (свапание `data-item`) дополняется свапанием новых data-атрибутов. UI (`renderCartBtn`, `initCartButtons`) не трогается.

После коммита: кнопки на странице цвета пишут в WC. `#stickyBar` остаётся как был (мёртвый, показывает 0 ₽). Простые товары (Салфетка, Куверт) тоже работают.

### Коммит 2: глобальная иконка корзины + модалка

ТЗ → `02-cart-icon-and-modal.md`

Добавляется:
- Новый файл `cart-widget.php` — HTML иконки + модалки/bottom-sheet
- Подключение `<?php get_template_part('cart-widget'); ?>` в `footer.php` (один раз → видно на всех страницах сайта)
- Новая секция `/* === CART WIDGET === */` в конце `style.css`
- Новая секция в `main.js`: открытие/закрытие модалки, загрузка содержимого через `loraleya_get_cart`, кнопки `+`/`−` внутри модалки, кнопка «Оформить заказ» → `/cart/`. Слушает кастомное событие `loraleya:cart-updated` (его диспатчит коммит 1).

После коммита: иконка работает на всех страницах, новая модалка работает параллельно со старым `#stickyBar` (полоска ещё есть). Это временное состояние на 1 коммит.

### Коммит 3: удалить `#stickyBar` со страницы цвета

ТЗ → `03-remove-sticky-bar.md`

Удаляется:
- В `taxonomy-pa_fabric_color.php` блок строк 581–589 (`<!-- 9. STICKY BAR -->` целиком)
- В `style.css` секции `.sticky-bar`, `.sticky-bar.show`, `.sb-info`, `.sb-dot`, `.sb-text`, `.sb-total`, `.sb-btn`, `.sb-btn:hover` (строки ≈2270–2331)
- В `main.js` обработчик `sbBtn` (строки ≈214–218) — небольшой блок внутри `if (document.querySelector('.color-hero'))`. Сам `if` оставить, удалить только содержимое про `sbBtn`.

После коммита: финальное состояние. Только глобальная иконка, никаких дублей.
