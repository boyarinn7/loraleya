## ЧАСТЬ 1. Закрытые решения — НЕ пересматривать

### 1.1. Позиционирование

**LoraLeya = премиум-сайт, не премиум-продукт.** Жаккардовый полиэстер позиционируется как практичный повседневный премиум, не как «не премиум».

В текстах:
- ❌ НЕ использовать в title/H1: «полиэстер», «не мнётся» (как SEO-ключ), «недорогой», «доступный», «столовый текстиль» (мёртвый термин)
- ✅ Использовать: «жаккардовая скатерть», «премиум», цвет, «набор», «комплект», «сервировка стола», «коллекция»

### 1.2. Терминология «куверт» vs «конверт»

Использовать ОБА термина в текстах. «Конверт для столовых приборов» (572 запроса) популярнее в Яндексе чем «куверт» (185), но «куверт» — бренд-термин LoraLeya.

В H1 карточки товара: «Конверты для столовых приборов (куверты)»
В описании: «Конверты для приборов, или куверты — это…»

### 1.3. Сценарии — финальная конфигурация (4 сценария)

| Сценарий (название на главной) | Title (для поиска) | Целевая семантика |
|---|---|---|
| Романтический ужин | Сервировка романтического ужина на двоих: стол при свечах \| LoraLeya | стол на двоих (109), романтический (89) |
| Семейный обед | Сервировка стола к обеду — для семейного обеда \| LoraLeya | сервировка стола обед (2127), сервировка обеденного стола (228) |
| Праздничный стол **(hub-страница: праздник + ДР + юбилей + свадьба)** | Сервировка праздничного стола: день рождения, юбилей, свадьба \| LoraLeya | сервировка праздничного стола (1495), сервировка стола на день рождения (616), свадебный (158) |
| Каждый день | Повседневная сервировка стола: текстиль на каждый день \| LoraLeya | повседневная сервировка стола (89) |

**КЛЮЧЕВОЕ:** «Праздничный стол» становится hub-страницей под ВСЕ праздничные события. Внутри страницы — отдельные блоки H2 «Сервировка стола на день рождения», «Юбилей», «Свадьба». Конструктор остаётся как есть. Это закрывает 2 главных праздничных кластера на одной странице.

**НЕ создаём отдельный сценарий «День рождения»** — добавление 5-й карточки на главной = некрасивый layout, экономия минимальная. Вместо этого:
- ДР внутри hub-страницы «Праздничный стол» (транзакционно)
- + статья блога «Сервировка стола на день рождения: 7 идей для взрослых и детей» (информационно)

**НЕ переименовываем «Семейный обед»** на главной — название карточки остаётся. Меняется только title/H1/description для поисковика.

### 1.4. Новые посадки (создаём в Спринте 2, не в Спринте 1)

| URL | Тип | Цель |
|---|---|---|
| `/nabory/` | Новая страница-категория | Закрыть наборную семантику (~1540 запросов/мес) |
| Усиление `/delivery/` | Правка существующей | Гео-Москва (~540 запросов/мес) |

**`/nabory/` — это отдельная посадка, НЕ блок внутри сценариев.** Дублирование блока про наборы на 4 страницах сценариев = дубль контента в глазах Яндекса, плохо для SEO. Нужна одна центральная посадка.

### 1.5. Блог — обязательно

**27 400 информационных запросов/месяц — это ОСНОВНОЙ канал органики.** Без блога стратегия не работает.

Темп: 1-2 поста в неделю.

Workflow:
1. Cron в GitHub Actions → Claude API → генерирует пакет из 4 версий поста (длинный для сайта + ТГ + ВК + ОК)
2. Бот в Telegram отправляет пакет Куренковой
3. Куренкова «очеловечивает» (1-2 фразы) и публикует
4. Куренкова сама дублирует в ТГ-канал/ВК (или бот автопостит — обсудим в Спринте 3)

Структура — 5 хабов:
1. Праздничная сервировка (~11 500 запросов)
2. Салфетки и складывание (~11 100)
3. Сервировка-гайды (~5 860)
4. Материалы и уход (~2 000)
5. Энциклопедия премиум-сервировки (~600+, ловит «что такое куверт» — 592)

### 1.6. AI-поиск (GEO) — учтено в редакционном гайде

Каждая страница и статья:
- Структура текстов: «вопрос → прямой ответ в 1-2 предложения → раскрытие»
- FAQ-блок с schema FAQPage
- Имя автора (Куренкова или редакционная команда) для E-E-A-T
- Внутренняя перелинковка 3-5 контекстных ссылок
- Таблицы и структурированная информация где уместно

В Спринте 4: llms.txt, полная schema (Organization, LocalBusiness, Product, Article, FAQPage, HowTo, BreadcrumbList).

### 1.7. Доставка в шаблонах description

Использовать «Бесплатная доставка от 100 000 ₽» как есть. Подтверждено клиентом, риск не критичный.

### 1.8. Конверсионные элементы (отложено в Спринт 3+)

- Программа лояльности (баллы) — обязательно для перевода WB-покупателей на сайт
- Вкладыши в WB-заказы с QR на сайт — на стороне Куренковой

### Формат сессии

- Без CSV и скриншотов — только текстом в чат


После этого — кластеризация и интеграция в семантику.

**Важно:** также при прогоне обратить внимание на правую колонку Wordstat «Запросы, похожие на …». Если там всплывают неожиданные релевантные формулировки — добавлять их в дополнительный пакет.

**Что нужно от Бориса:**

**Создаём после Блока B (когда бежевый отлажен):**
1. Title-шаблон: «{Цвет}ая жаккардовая скатерть и дорожка — {N} наборов | LoraLeya»
2. Description-шаблон с переменной `{описание оттенка}`
3. 16 индивидуальных описаний оттенков (по 2-3 предложения каждое — это уникальная часть для каждой страницы)
4. Базовый текст 400-600 знаков (шаблонный + подстановка цвета и описания)
5. FAQ-блок шаблонный (одни и те же 4-5 вопросов на всех цветах)

**Глубина текста зависит от объёма семантики:**
- Бежевый (598) — глубокая посадка ✅ (сделано в Блоке B)
- Бирюза, графит, серый, чёрный (10-80) — стандартный шаблон
- Бронза, металлик, золото, кораллы, оливка и т.д. (0-30) — короткие шаблонные

#### Блок D. Сценарии — переписываем 4 страницы

**Приоритет по объёму семантики:**
1. **Семейный обед** (2355 запросов) — переписываем полностью, расширенный текст
2. **Праздничный стол hub** (2270 запросов) — переписываем полностью + добавляем H2-блоки про ДР, юбилей, свадьбу
3. **Романтический ужин** (198 запросов) — обновляем title/description, короткое обновление текста

**Что нужно от Бориса для каждой:**

#### Блок E. Карточки 220 SKU — НЕ в Спринте 1

Отложено в Спринт 4 вместе с установкой Rank Math. Причина: без SEO-плагина невозможно эффективно управлять meta-полями 220 карточек. Любая ручная или скриптовая правка сейчас → потом конфликт с плагином → двойная работа.

В Спринт 4 — устанавливаем Rank Math и через него массово настраиваем title/description по шаблонам.

### Порядок выполнения Спринта 1

**A → B → ⏸ ревью → C → D**

После Блока B (бежевый) — короткое **ревью-окно**:
- Смотрим как бежевый ложится в боевую среду
- Проверяем шаблон страницы цвета (вёрстку, FAQ, перелинковку)
- Только после этого масштабируем на 16 цветов в Блоке C

Если шаблон кривой, переделывать придётся 16 раз. Дешевле проверить на одном.

### Оценка времени Спринта 1

- Блок A (главная) — 2-3 рабочих сессии
- Блок B (бежевый) — 2 сессии (черновик + ревью + финал)
- Блок C (16 цветов) — 4-5 сессий (с ревью каждых 4-5 цветов)
- Блок D (4 сценария) — 3-4 сессии (по 2 крупным сценариям + 1 на короткие)

**Итого:** 11-14 рабочих сессий = 3-4 недели при темпе 4-5 сессий в неделю.
