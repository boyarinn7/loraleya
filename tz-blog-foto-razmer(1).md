# ТЗ — Размер фото в теле статей блога (LoraLeya)
*Для Code-Клода. Дата: 23.06.2026. Автор: SEO-Клод (роль веб-дизайнера). Передаёт Борис. Канал: прямой (не через Спринт-Клода — он на адаптиве).*

## Проблема (диагноз по измерениям, не на глаз)
На странице статьи (`/blog/{slug}/`, шаблон `single.php`, обёртка тела `.article-body`):
- Текстовая колонка = **759px**. Фото в теле = тоже **759px**, выровнены по колонке — это **правильно, ширину не трогаем**.
- Дефект: в CSS у `.article-body` (style.css, ~строка 4066) есть правила для `h2/h3/p/ul/ol/li/a/strong/table`, но **нет ни одного правила для `img`**. Картинки рендерятся в нативном размере: квадраты ~759×759. На ноутбуке (~768px высоты экрана) каждое фото занимает почти весь экран → статья читается как слайдшоу. Это и есть «смущает размер».

## Задача
Ограничить фото по **высоте** и центрировать, сохранив аспект (НЕ кадрировать — для пошаговых складок важна вся фигура). Width не менять.

## Решение — добавить в `style.css`
В конец блока стилей блога (после `.blog-card__img`, ~строка 4131):

```css
/* Фото в теле статьи */
.article-body figure { margin: 2rem auto; text-align: center; }
.article-body img {
  display: block;
  margin: 2rem auto;
  max-width: 100%;
  max-height: min(520px, 70svh);  /* потолок высоты: не выше 520px И не выше 70% экрана */
  width: auto;
  height: auto;
  border-radius: 6px;
}
.article-body figure img { margin: 0 auto; }
.article-body figcaption {
  margin-top: .6rem;
  font-size: .85rem;
  font-style: italic;
  color: rgba(232, 224, 208, .6);
  text-align: center;
}
```

`min(520px, 70svh)` — одно правило на все экраны: на обычных/больших мониторах работает 520px (фото не раздувается), на коротких окнах и телефоне срабатывает 70svh (фото ужимается под экран). `svh` стабилен на iOS (не прыгает от адресной строки). Отдельный мобильный `@media` не нужен. Рендерится одинаково во всех браузерах — `min()` и `svh` в 2026 поддерживаются везде.

Это правило по селектору `.article-body img` — действует на ВСЕ картинки во ВСЕХ статьях блога автоматически, включая те, что добавят позже. Доп. правок под новые фото не требуется.

## Гейт — проверить в разметке (по скрину не видно)
1. **CLS:** у `<img>` должны быть атрибуты `width`/`height` (Gutenberg обычно ставит). Без них `max-height` даст дёрганье вёрстки при загрузке. Если атрибутов нет — добавить.
2. **LCP/скорость:** `loading="lazy"` на всех фото в теле **кроме первого** (первое — кандидат в LCP, lazy на нём вредит скорости). Если на первом стоит lazy — снять; на остальных проставить.

## Приёмка
- Десктоп: ни одно фото не занимает весь экран; визуальная высота фото ровная по статье.
- Мобайл (≤640): фото (в т.ч. будущий портрет) не съедает весь экран.
- Скругление углов и вертикальные отступы на месте; выравнивание по центру.
- Проверить заодно остальные 3 статьи блога — правило применилось ко всем, нигде не сломало вёрстку.
- Очистить кэш после правки.

## Примечание
- В `min(520px, 70svh)` подбираемые оба числа: `520px` — потолок на больших экранах (тюнинг 480–560px), `70svh` — доля экрана на коротких окнах/мобиле (тюнинг 60–75svh).
- Фото №2 в этой статье добавляется позже — отдельных действий не требует, подхватится правилом.
