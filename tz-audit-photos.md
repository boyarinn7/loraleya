# ТЗ (диагностика) — Полный аудит фото в Media Library

**Адресат:** Claude Code agent в VS Code
**Тип:** ТОЛЬКО ЧТЕНИЕ + генерация отчёта. НИЧЕГО не меняем, не загружаем, не удаляем.
**Зачем:** Sprint-Клоду нужна точная карта какие фото есть, каких не хватает, под какими именами. По этому отчёту составится чек-лист на досъёмку.
**Результат:** один текстовый/HTML отчёт, который Борис передаёт Sprint-Клоду.

## Контекст — как устроены имена файлов (важно!)

В теме фото ищутся функцией `loraleya_get_color_photo_url($color_slug, $type)`. Логика:
1. slug цвета **переводится в префикс файла** по карте (slug в j-схеме, префикс в y-схеме — НЕ совпадают!)
2. имя attachment'а (поле `post_name`/`post_title`) = `{префикс}-{тип}`
3. фолбэк — `{префикс}-{тип}-scaled`

## Задача — сгенерировать отчёт

Создай PHP-скрипт `tools/audit-photos.php` (по образцу `tools/import-photos.php`: загрузка `wp-load.php`, проверка `manage_options`, HTML-вывод). **Скрипт только читает БД и выводит отчёт, ничего не пишет.**

### Что скрипт должен сделать

1. Задать в коде карту префиксов (из таблицы выше) и список 12 типов.
2. Для каждого из 17 цветов × 12 типов:
   - сформировать ожидаемое имя `{префикс}-{тип}`
   - проверить через `get_posts(['post_type'=>'attachment','name'=>$title,...])` — есть ли attachment
   - проверить фолбэк `{префикс}-{тип}-scaled`
   - если найдено — взять реальные размеры файла (`wp_get_attachment_metadata` → width/height) и записать ✅ + размеры
   - если не найдено — записать ❌
3. Вывести **матрицу-таблицу**: строки = 17 цветов, колонки = 12 типов, в ячейке ✅ (с размером) или ❌.
4. Вывести **итоговый список пробелов** отдельным блоком: построчно `{цвет} — не хватает: {тип1}, {тип2}, ...` — это самое нужное Sprint-Клоду.
5. Подсчитать: всего фото в наличии / всего пробелов / процент готовности.
6. Отдельно проверить «осиротевшие» attachment'ы: вывести все attachment'ы, чьё имя начинается с любого из 17 префиксов, но НЕ совпадает ни с одним ожидаемым `{префикс}-{тип}`. Это покажет файлы, загруженные под «неправильными» именами (например `platina-skatert-1` вместо `platina-skatert`, или с лишним суффиксом). **Это закроет вопрос пропавшей скатерти.**

### Отдельный фокус — скатерть на главной

Главная запрашивает `platina-skatert` (страница «Палитра» / блок «Что входит в сервировку»). Скатерть там не отображается. В отчёте отдельной строкой:
- есть ли attachment `platina-skatert` (или `platina-skatert-scaled`)?
- если нет — есть ли что-то похожее (`platina-skatert-1`, `platina-skater`, `skatert-platina` и т.п.)?
- вывести ВСЕ attachment'ы, в имени которых есть `skatert`, по всем цветам — чтобы увидеть как скатерти реально названы в библиотеке.

## Что вернуть Борису

Скопируй **весь вывод отчёта** (или сделай скриншот целиком — он длинный, можно частями) и передай Sprint-Клоду. Особенно важны блоки 2 (список пробелов), 3 (скатерть), 4 (осиротевшие).

---

## Что НЕ делает скрипт

1. НЕ загружает, не удаляет, не переименовывает фото
2. НЕ трогает товары, записи, термины
3. НЕ меняет код темы (кроме создания самого `audit-photos.php`)
4. Только читает БД и выводит отчёт

После того как Sprint-Клод построит чек-лист досъёмки — `audit-photos.php` можно удалить (или оставить как инструмент для повторных проверок по мере поступления фото).
