# LoraLeya — устойчивые решения

- 2026-08-22 — Production и `main` не изменять без отдельного подтверждения: это действующий сайт и default branch.
- 2026-08-22 — Staging-first: все изменения сначала проверяются на закрытом `/test/`.
- 2026-08-22 — Ручные approval dialogs Codex сохраняются: критичные действия требуют явного контроля пользователя.
- 2026-08-22 — Индивидуальный заказ оплачивается по схеме 50% + 50% согласно оферте, а не как 100% предоплата.
- 2026-08-22 — Доставка индивидуального заказа оплачивается отдельно по согласованному способу.
- 2026-08-22 — YooKassa сама сообщает клиенту о факте оплаты и чеке; письма LoraLeya не дублируют это подтверждение.
- 2026-08-22 — `customer_processing_order` означает, что заказ принят LoraLeya в работу.
- 2026-08-22 — `customer_completed_order` означает, что заказ передан перевозчику и находится в пути.
- 2026-08-22 — Completed email содержит универсальный трек-номер заказа, если он заполнен.
- 2026-08-22 — Для ПВЗ сообщается, что служба доставки уведомит о готовности к получению.
- 2026-08-22 — Для курьера используется фраза «Курьер свяжется с вами перед доставкой.»
- 2026-08-22 — 5Post всегда рассматривается как доставка в ПВЗ; отправления создаются менеджером вручную.
- 2026-08-22 — Технический публичный товар для индивидуальных заказов не создавать; `product_id = 0` сохраняется.
- 2026-08-22 — Fivepost metabox guard для индивидуальных заказов сохраняется, чтобы защищать admin от `product_id = 0`.
- 2026-08-22 — `customer_note` обычного заказа остаётся максимально коротким: приветствие, номер, заметка, бренд-футер.
- 2026-08-22 — Клиентские письма исправляются изолированно, одно за другим; массовый рефакторинг email architecture без подтверждённой необходимости не выполнять.
- 2026-08-22 — После завершённого логического блока создавать checkpoint/commit и обновлять состояние проекта.
- 2026-08-22 — Критические персональные и секретные credentials никогда не помещать в документацию.
