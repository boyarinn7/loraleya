*Бридж от Спринт-Клода по `tz-adaptiv-mobile-tablet.md` (4.C). A и B приняты. C разбита на C1 (сценарий, классы `.ir/.qb/.total-sticky`) и C2 (индивидуальный заказ, классы `.co-*`) — берём C1.*

**Файл:** `style.css`. (Разметку `single-scenario.php` НЕ трогаем — структура `.ir` уже подходящая.)
**Гейты:** rem; новый `!important` не плодить; ноль CLS; тач ≥44×44; НЕ трогать логику корзины/цены/тексты/разметку.

**Структура строки (подтверждена по `single-scenario.php`):**
```
.ir > [ <div>(.ir-name + .ir-size) , .ir-price , .ir-qty(.qb − .qv + .qb) , .ir-sub ]
```
4 прямых потомка; первый — безклассовая обёртка имени+размера.

## 1. Двухстрочная позиция — заменить блок ≤1024

**Найти** (существующий блок):
```css
@media (max-width: 1024px) {
    .con {
        padding: 2rem 1.5rem;
    }
    .total-sticky {
        padding: 1rem 1.5rem;
        margin: 0 -1.5rem -2rem;
    }
    .ir {
        grid-template-columns: 1fr;
        gap: 0.4rem;
    }
    .ir-price,
    .ir-sub {
        text-align: left;
    }
}
```

**Заменить на:**
```css
@media (max-width: 1024px) {
    .con {
        padding: 2rem 1.5rem;
    }
    .total-sticky {
        padding: 1rem 1.5rem;
        margin: 0 -1.5rem -2rem;
    }
    /* Позиция набора в 2 строки: имя сверху, цена·кол-во·сумма снизу */
    .ir {
        grid-template-columns: 1fr auto 1fr;
        grid-template-areas:
            "name  name name"
            "price qty  sub";
        gap: 0.4rem 0.75rem;
        align-items: center;
    }
    .ir > div:first-child { grid-area: name; }
    .ir-price { grid-area: price; text-align: left; }
    .ir-qty   { grid-area: qty;   justify-content: center; }
    .ir-sub   { grid-area: sub;   text-align: right; }
}
```
Результат: строка 1 — название + размер на всю ширину; строка 2 — цена (слева) · кнопки кол-ва (центр) · сумма (справа). Никаких 4 отдельных строк.

## 2. Тач-размер кнопок ± — добавить В КОНЕЦ `style.css`
```css
/* Адаптив C1: кнопки ± в конструкторе под палец (≥44px на тач) */
@media (pointer: coarse) {
    .qb { width: 2.75rem; height: 2.75rem; font-size: 1.1rem; }
    .qv { min-width: 2rem; }
}
```
(Сейчас `.qb` = 1.625rem ≈ 26px — мало. 2.75rem = 44px. `.qv` шире, чтобы число не прыгало.)

## 3. Sticky-бар на iOS — ПРОВЕРИТЬ, фикс применять только при проблеме
`.total-sticky` = `position:sticky; bottom:0` + отрицательные margin. На iOS Safari это иногда дёргается/перекрывает последнюю позицию.
- **Сначала проверить** на реальном iOS Safari (или эмуляции): бар плавно стоит внизу, не прыгает при скролле, не перекрывает последнюю позицию набора.
- **Только если дёргается/перекрывает** — добавить В КОНЕЦ `style.css`:
```css
/* Применять ТОЛЬКО если sticky-бар дёргается на iOS */
@media (max-width: 768px) {
    .total-sticky {
        position: fixed;
        left: 0; right: 0; bottom: 0;
        margin: 0;
        padding: 1rem 1.5rem;
    }
    .con { padding-bottom: 6rem; } /* место под фикс-бар; подогнать под реальную высоту бара */
}
```
Это итеративный шаг — высоту `padding-bottom` подогнать на устройстве, чтобы последняя позиция не пряталась за баром.

## 4. Что НЕ делаем
- Не трогаем разметку `single-scenario.php`, логику цен/корзины, базовый `.ir` грид для десктопа (>1024).
- Не лезем в конструктор индивидуального заказа (`.co-*`) — это C2, отдельно.

## 5. Приёмка (1024 / 768 / 414 / 360, скрин на каждом)
1. Позиция набора — **в 2 строки**: имя сверху, под ним цена · ± · сумма в один ряд (не 4 строки).
2. Кнопки ± жмутся пальцем (≥44px), число между ними не прыгает при изменении.
3. Цена слева, сумма справа, кнопки по центру — читаемо, без горизонтального скролла.
4. Sticky-бар «В корзину» внизу не дёргается и не перекрывает последнюю позицию (на iOS — особое внимание; при проблеме применён фикс из п.3).
5. Добавление набора / изменение количества работает на тач.
